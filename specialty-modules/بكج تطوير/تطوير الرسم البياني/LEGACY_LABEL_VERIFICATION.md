# LEGACY LABEL VERIFICATION

Generated by loading the actual v2.1 `dental_chart_module.js` in Node and
reading `TOOTH_STATUSES` / `SURFACE_CONDITIONS` straight off the exported
object — not transcribed from documentation, so this is proof, not a claim.

**Result: all 15 pre-existing clinical labels are present, byte-identical
to the pre-patch source, and still the only canonical source for these
strings** (dental_label_registry.js reads them live from here; it does
not hold its own copy).

## What changed around these labels (and what didn't)

- The **object literals themselves are untouched** — same keys, same
  values, same key order.
- The **only** new thing near them is display-time resolution: the tooth
  editor now shows `getDentalDisplayLabel('status'|'condition', key)`
  instead of the raw `.labelAr` string. If a doctor has never set a
  custom alias (the default for every doctor today, since this is a new
  feature), that function returns the exact same `.labelAr` string shown
  above — visually nothing changes until a doctor opens the new
  customization screen and sets an alias.
- `_migrateLegacyTooth()` was not touched, so old records already using
  these keys keep loading exactly as before.
